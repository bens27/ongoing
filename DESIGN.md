# Ongoing's design system

Ongoing's frontend is a dense, quiet, keyboard-first inventory. It starts from the Linear patterns
and drifts into a house style on purpose; this document is where the drift is written down, so the
drift stays deliberate rather than accidental (ADR
[0008](docs/adr/0008-frontend-design-system.md)).

Screens are in [`docs/qa/screens/`](docs/qa/screens/), dark and light. Regenerate them with:

```sh
QA_SCREENSHOTS=1 E2E_PORT=7801 bun run test:e2e tests/e2e/screenshots.test.ts
```

## The five rules

1. **Tokens, never per-component values.** Every colour, size, duration, and weight in the app
   resolves to a custom property in [`src/lib/ui/tokens.css`](src/lib/ui/tokens.css). No component
   declares a `font-size` in pixels or a colour literal. This is the whole reason the old
   `dashboard.css` was replaced rather than restyled: it had an absolute `font-size` per component,
   so an app-wide type change meant editing 1,468 lines.
2. **The registry decides what renders.** Columns, cells, editors, the generic fact-sheet
   sections, and the project overview's field inspector are driven by `FieldDefinition`s, so
   `ongoing field add x.customer --type text` makes a field visible, sortable, filterable, and
   editable in the browser with no frontend change. The project overview chooses which fields to
   lead with; it never decides which fields exist.
3. **Flat data, elevated overlays.** Data surfaces are sharp-edged, borderless-except-1px, and
   never carry a shadow. `border-radius` and `box-shadow` belong to the palette and nothing else.
4. **Colour means status.** The neutral scale carries the interface. Colour appears in a `Badge`
   tone, an accent on an active nav item or a focus ring, and nowhere else.
5. **Every mutation has a CLI verb.** A button that no `ongoing` command can press is a bug, not a
   feature. Palette commands print their CLI equivalent as their hint, which keeps the two honest.

## Tokens

### Colour

Dark is the base theme; `@media (prefers-color-scheme: light)` supplies the light variant and
`html[data-theme="dark"|"light"]` overrides both. Values are `lch()` — perceptually uniform, so a
lightness step looks like the same step at every hue — generated by hand from two variables,
`--base-hue` and `--accent-hue`.

| Group     | Tokens                                                                      | Use                                                                 |
| --------- | --------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| Surface   | `--bg-canvas`, `--bg-surface`, `--bg-inset`, `--bg-raised`                  | canvas is the list; inset is the rail and table head; raised floats |
| State     | `--bg-hover`, `--bg-selected`                                               | row hover, the row the keyboard is on                               |
| Text      | `--text-primary`, `--text-secondary`, `--text-tertiary`, `--text-on-accent` | value, label, meta; tertiary never carries prose                    |
| Border    | `--border-strong`, `--border-default`, `--border-subtle`                    | section edges, controls, row separators                             |
| Accent    | `--accent`, `--accent-hover`, `--accent-tint`                               | active nav, focus ring, primary action                              |
| Status    | `--status-ok\|warn\|error\|info\|muted` and each one's `-tint`              | badge tones only                                                    |
| Elevation | `--shadow-overlay`, `--overlay-backdrop`                                    | the palette, the actions menu, the inspector dialog. Nothing else.  |

A Playwright test asserts `--text-primary` at 7:1 and `--text-secondary` at 4.5:1 against the body
background in both themes, and `--text-tertiary` at 3:1 — it labels and counts, never prose.

### Type

One family, one scale, three weights. `--font-sans` is Inter with a system fallback stack;
`--font-mono` carries paths, slugs, queries, versions, and every number in a column.

| Token        | Size   | Where                                                                |
| ------------ | ------ | -------------------------------------------------------------------- |
| `--text-2xs` | 11px   | section headings, counts, key hints, badge text                      |
| `--text-xs`  | 12px   | controls, fact-sheet key/value rows                                  |
| `--text-sm`  | 13px   | the density default: rows, inputs, body                              |
| `--text-md`  | 15px   | panel and page titles                                                |
| `--text-lg`  | 20px   | an entry's name on its generic fact sheet; the work and CI headlines |
| `--text-xl`  | 25.6px | the project overview's headline: its name, and commits in 30 days    |
| `--text-2xl` | 29.6px | the other signal headlines: stars, lines of code                     |

`--text-xl` is 1.6rem, down from the 1.85rem of the design study, so a panel beside the inventory
does not shout. It is the one size the overview's name and its "is it moving" number share; no
other metric borrowed the reduction, which is why `--text-2xl` still exists.

Four letter-spacing tokens go with the scale. `--tracking-label` (0.06em) opens up the small
uppercase heading of a section and `--tracking-eyebrow` (0.09em) the eyebrow above a panel title;
`--tracking-tight` (-0.03em) closes a name a little and `--tracking-headline` (-0.05em) a headline
number more, as large sizes ask.

### Space and shape

`--space-1` through `--space-8` are a 4px grid, plus `--space-half` (2px) for the one gap a
stacked label/value pair needs. `--row-height` is 30px and `--header-height` 40px, which is what
makes the table read as a spreadsheet rather than a list of cards. `--radius-sm` and `--radius-md`
apply to buttons, inputs, badges, chips, and the palette; data surfaces get none.

Every separator is `--rule` (1px); `--rule-strong` (2px) underlines the selected signal tab and
nothing else. A component never writes a border width of its own.

| Group    | Tokens                                                                                                   | Use                                                                                                                                                        |
| -------- | -------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Panel    | `--panel-width` 400px, `--panel-width-wide` 520px                                                        | every detail panel; the project overview asks `Panel` for the wide variant, which gives its width back below 1366px so the list keeps six readable columns |
| Sheet    | `--factsheet-max-width` 1240px, `--factsheet-columns`                                                    | the project fact sheet's two-column arrangement, capped so a line never runs an ultrawide monitor; one column below 860px                                  |
| Overview | `--identity-mark-size`, `--rate-label-width`, `--rate-value-width`, `--track-height`, `--split-cell-min` | the identity mark, the three columns of a rate bar row and its track, and the narrowest cell of a split-metric row                                         |
| Chart    | `--chart-height` 120px                                                                                   | the height of a dated chart's drawing; the loading, empty, unavailable, and error states are one line of copy with padding, not a chart-sized blank        |
| Rows     | `--kv-label-min`, `--kv-label-max`                                                                       | the label column of a key/value row, capped so a wide sheet does not stretch it                                                                            |
| Floating | `--menu-width`, `--dialog-width`, `--dialog-max-height`, `--pre-max-height`                              | the actions menu, the field inspector dialog, and the raw-value block inside it                                                                            |

The two breakpoints live in `Panel.svelte` and `ProjectFactsheet.svelte` as literals, because a
media query cannot read a custom property; each one says so in a comment beside the token it pairs
with.

sits and what the chart says about itself), `history-client.ts` (the browser's cached read of

to), `catalog.svelte.ts` (the client store and the one place a mutation happens).

## The project overview (`src/lib/ui/project/`)

Opening a project answers four questions in order: what is this, what needs me, is it moving, and
where is the evidence. The inventory panel and the `/p/<slug>` fact sheet are two compositions of
one set of sections over one presentation model; a wider screen changes where a section sits,
never what it says. Neither surface holds a rule of its own: `projectOverview` in `overview.ts`
prepares every summary, action, and evidence line from the entry, the registry, and the clock,
and `selectPriority` in `src/lib/domain/priority.ts` decides what leads.

| Component                                                                                      | What it is                                                                                                                                                                              |
| ---------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ProjectPanel.svelte`                                                                          | The panel composition: identity, priority, signals with tabs, then the four disclosures, the inspector in the footer. Keyed by entry id so state resets per project.                    |
| `ProjectFactsheet.svelte`                                                                      | The sheet composition: identity beside priority, Activity/Codebase with Work and Repository on the left, Reach with Stack and Notes on the right. One column below 860px, in DOM order. |
| `ProjectIdentity.svelte`                                                                       | Mark, name (the page's `h1` on the sheet), purpose, intent, visibility, links. Rename in place.                                                                                         |
| `ProjectPriority.svelte`                                                                       | One primary reason with its action, "Why this?" evidence, and `+N more`; or the stored next action; or a calm empty state.                                                              |
| `ProjectSignals.svelte`                                                                        | The Activity, Reach, and Codebase tabs — one Tab stop, arrows between them. The sheet passes `tabs` to keep Reach out and renders `ReachSection` beside it.                             |
| `ActivitySignal.svelte`                                                                        | Commits in 30 days at `--text-xl`, active days, three disjoint rate bars, commits in 7 days, merged PRs, contributor scope.                                                             |
| `ReachSignal.svelte`                                                                           | Stars and the applicable audience metrics over the dated star chart; a private repository gets no chart; traffic is a secondary summary with its real window.                           |
| `CodebaseSignal.svelte`                                                                        | Lines of code over the dated LOC chart, file count, size context. Not a productivity or coverage score.                                                                                 |
| `ReachSection.svelte`                                                                          | The fact sheet's always-visible Reach: the same `ReachSignal` the panel keeps behind a tab, under its own heading.                                                                      |
| `SignalHistory.svelte`                                                                         | Reads one metric through `history-client.ts` for the visible tab, ignores a response that arrives after the project changed, and renders its state explicitly.                          |
| `DatedChart.svelte`                                                                            | The line over dated observations, one Tab stop with arrow keys between points, an `aria-label` summary and a live readout.                                                              |
| `Disclosure.svelte`                                                                            | A `<details>` whose summary line is useful when closed. Work, Repository, Stack, and Notes are four of them; their open state survives a tab switch and a refresh.                      |
| `WorkSection.svelte`, `RepositorySection.svelte`, `StackSection.svelte`, `NotesSection.svelte` | The four disclosures: issues, PRs, and td; CI, branch, and divergence; technologies with versions and evidence; editable notes and decisions.                                           |
| `ActionsMenu.svelte`                                                                           | The infrequent actions — favourite, hide, rename, copy path, terminal, repository, website, palette — from `menu.ts`, so the two surfaces cannot drift.                                 |
| `FieldInspector.svelte`                                                                        | "All fields & sources": a searchable dialog over every registered field, custom and empty ones included, with provider, timestamps, errors, relations, and the typed editor.            |

The rules these components render, so that nobody re-derives them in a view:

- **Priority is a documented ranking, not array order.** `priority.ts` places every classified
  reason in one of five tiers — failures and blockers, overdue external work, missing decisions,
  context, positive signals — and breaks ties by source, input, then view. Only the first three
  tiers may lead; when nothing reaches them the overview shows the stored next action, never an
  invented task or a health score.
- **Rates are disjoint.** The collectors store cumulative windows, so the three bars are
  `(commits90d − commits30d) / 60`, `(commits30d − commits7d) / 23`, and `commits7d / 7`, labelled
  days 90–31, days 30–8, and last 7 days. Inconsistent inputs draw no bar rather than a negative
  one, and nobody manufactures daily history from three totals.
- **A chart is dated observations.** Points sit by date on the observed range; a y-axis that does
  not start at zero says so. A missing date is an interpolation, drawn dashed and labelled when
  the gap is seven days or more; a null breaks the line. No observations, one observation, a
  constant series, and a provider that could not collect are four different sentences, and none
  of them is a row of dashes.
- **Colour still means status.** Charts, bars, and the selected signal tab (a strong rule in the
  text colour) use the text scale; the only colour on the overview is a badge tone, the accent on
  the primary action, the focused chart point, the favourite star and inline links, and the focus
  ring.
- **Edits go through `Catalog`.** A next action typed into the panel, the sheet, or the inspector
  is the same optimistic patch as a cell edit: validated first, rolled back on failure, undone by
  `u`, and reachable as `ongoing set`.

## Keyboard map

The filter's `?` button (or `?` outside a text input) opens `QueryHelp.svelte`, a native modal
with syntax examples and a searchable reference from the live field registry. Trying an example
replaces the filter and leaves saved-view mode. Escape closes only the help and returns focus to
its trigger. The body scrolls independently so the title and close button stay available on phones.

| Key           | Does                                                                                                      | CLI equivalent                         |
| ------------- | --------------------------------------------------------------------------------------------------------- | -------------------------------------- |
| `j` / `k`     | move down / up the list                                                                                   | —                                      |
| `Enter`       | open the detail panel on the focused row                                                                  | `ongoing show <entry>`                 |
| `Esc`         | close the editor, then the inspector or menu, then the panel                                              | —                                      |
| `/`           | focus the filter; `Enter` puts it in the URL                                                              | `ongoing list '<query>'`               |
| `,`           | the sort menu                                                                                             | `ongoing list --sort <keys>`           |
| `c`           | the column chooser                                                                                        | `ongoing list --columns <keys>`        |
| `e`           | edit the first editable column of the focused row                                                         | `ongoing set <entry> <field> <value>`  |
| `f`           | toggle favourite                                                                                          | `ongoing favorite <project>`           |
| `x`           | toggle hidden                                                                                             | `ongoing hide <project>`               |
| `u`           | undo the last edit                                                                                        | `ongoing set <entry> <field> <old>`    |
| `←` / `→`     | in the signal tabs, switch lens; in a chart, step between dated observations (`Home` / `End` to the ends) | `ongoing history <entry> --metric <m>` |
| `Cmd/Ctrl+K`  | the palette                                                                                               | —                                      |
| `g p` / `g t` | projects / technologies                                                                                   | `ongoing list 'kind:…'`                |
| `g r` / `g i` | radar / inventory                                                                                         | `ongoing tech list`                    |

## The URL is the query

`?q=`, `?sort=`, `?columns=`, and `?saved=` carry exactly the strings the CLI flags and the API
parameters carry, built with `formatQuery` and `formatSort`. `?entry=kind/slug` is the one piece of
state that is not part of the query — which row the panel is on — and it is in the URL for the same
reason: a link to a row should be a link to a row.

`listDefaultClauses` in `src/lib/domain/query.ts` is shared with `ongoing list`: both prepend
`kind:project` and `is_hidden:false` when the query has not spoken about them. The filter box shows
the _effective_ query, defaults included, so nothing is hidden state.

## Optimistic editing

`src/lib/domain/optimistic.ts` is pure and unit-tested. An edit:

1. runs `validateEntryPatch` against the registry — the same function the API and the CLI run, so
   the browser shows the CLI's error text before it sends anything;
2. applies the patch to a copy of the entry and re-runs `classifyAttentionViews`, so a row leaves
   `view:dormant` the moment its intent changes rather than a round trip later;
3. `PATCH`es `/api/entries/:kind/:slug` and replaces the row with the server's answer;
4. on failure, puts the entry it kept back and says why, inline.

Undo is `inversePatch` sent through the same endpoint — a patch like any other, so it validates,
re-classifies, and is itself a thing the CLI could have done.

## Deliberate drift from the Linear patterns

- **No web font.** Inter is requested and a system stack answers when it is absent. Ongoing runs on
  a LAN and should not reach Google Fonts to render a table.
- **Icons are vendored, not a dependency.** roc is not on a registry, so the 37 glyphs this UI uses
  live in `src/lib/ui/icons.ts` as their inner SVG markup. Adding one means copying the inner
  markup of the matching file in `~/code/roc/dist/svg/outline`.
- **The detail panel does not float.** Linear slides a panel over the list with a shadow. Ours is a
  grid column with a 1px left border: `Enter` must not take the keyboard away from the list. The
  project overview widens it to 520px rather than opening a second surface, and gives the width
  back below 1366px rather than squeezing the list.
- **The dated chart is a line; the sparkline is bars.** `Sparkline` draws three cumulative
  buckets, and a line there would imply a resolution the data does not have. `DatedChart` draws
  stored observations at their capture dates, so a line between two points is an honest
  interpolation — dashed and labelled when the gap is wide — and a null is a break, not a zero.
- **`svelte/no-navigation-without-resolve` is off.** The rule wants a literal `resolve()` in every
  `href`, and every URL this shell builds is computed — a query string, or an entry href from a
  kind and a slug. Ongoing has no `base` path, so the rule buys nothing it can enforce here.
- **The filter is a query string, not a builder.** Linear composes filters from menus. The grammar
  is the product here: a filter someone types is a CLI command they can paste.
- **No drag reorder.** `manual_rank` is still a sort key; reordering is a palette command and
  `ongoing set <entry> manual_rank <n>`. A drag that only works when nothing is filtered was a
  feature with a footnote.
- **Toolchain views with no members are hidden from the rail.** Ongoing ships a `stack-<toolchain>`
  view for every toolchain it knows; showing the eleven a machine has nothing in would bury the two
  it does. `ongoing views` still lists them all.

## Adding to this

- A new field: register it. Nothing in `src/lib/ui/` should need to know its key.
- A new screen: it belongs in `src/routes/(inventory)/` under the shell, reads the catalog from
  `getCatalogContext()`, and mutates only through `Catalog`.
- A new colour: it does not exist. Use a `Badge` tone, or add a token here first and say what it
  means.
- A new interaction: give it a key, give it a CLI verb, and add both rows to the table above.
- A new overview section: a component in `src/lib/ui/project/` whose summary comes from
  `overview.ts`, composed by both `ProjectPanel` and `ProjectFactsheet`. A section that exists on
  one surface and not the other is a bug; a rule that lives in the component instead of the model
  is the same bug one step earlier.
